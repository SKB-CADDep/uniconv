# Миграция с UniConv 1.x

[Все разделы](README.md) · [API](api.md) · [Единицы](units.md)

В 2.0 изменились аргументы конвертации и идентификаторы величин. Проверьте потребителей библиотеки перед обновлением зависимости с 1.x.

| В 1.x | В 2.0 |
|---|---|
| `parameter_type="pressure"` | `type_id="0"` |
| `from_unit="бар", to_unit="МПа"` | `from_u="бар", to_u="МПа"` |
| Обозначение единицы, например `кгс/см²` | Точный код `кгс/см2`; UI-обозначение берите из `get_available_units()`. |
| Список строк из `get_available_units()` | Список словарей с `code` и `ui`. |
| Расширение по имени параметра | `add_parameter()` и `add_unit()` со строковым ID. |

```python
from uniconv import UnitConverter

uc = UnitConverter()
# 1.x: uc.convert(10, from_unit="бар", to_unit="МПа", parameter_type="pressure")
assert uc.convert(10, from_u="бар", to_u="МПа", type_id="0") == 1.0
```

## Сопоставление встроенных величин

| Имя в 1.0.1 | ID в 2.0 | Базовая единица в 1.0.1 | Базовый код в 2.0 |
|---|---|---|---|
| `pressure` | `"0"` | `кгс/см²` | `кгс/см2` |
| `temperature` | `"1"` | `°C` | `C` |
| `mass_flow_rate` | `"2"` | `т/ч` | `т/ч` |
| `density` | `"5"` | `кг/м³` | `кг/м3` |
| `specific_volume` | `"6"` | `м³/кг` | `м3/кг` |
| `specific_enthalpy` | `"9"` | `ккал/кг` | `ккал/кг` |
| `specific_entropy` | `"10"` | `ккал/кг·K` | `ккал/(кг*С)` |
| `dryness_fraction` | `"11"` | `%` | `-` (доля) |
| `power` | `"17"` | `МВт` | `МВт` |
| `heat_power` | `"18"` | `Гкал/ч` | `Гкал/ч` |

У степени сухости изменилась базовая единица: старое базовое значение `95` означает 95 %, а новое — `0.95`. Если в хранилище уже лежит доля, повторно пересчитывать её не нужно. Код доли в 2.0 — `-`.

```python
from math import isclose
from uniconv import UnitConverter

uc = UnitConverter()
old_percent = 95
new_base_value = uc.to_base(old_percent, "%", "11")
assert isclose(new_base_value, 0.95)
```

Для хранимых данных сверяйте ID, коды и базовые единицы по [реестру 2.0](units.md). Значения, которые хранились в прежней базовой единице, сначала сопоставьте с её фактическим кодом; не подставляйте новую базовую единицу без проверки. Точные физические константы в 2.0 могут изменить результаты по сравнению со старыми округлёнными коэффициентами.

Если приложение читало или изменяло внутренний словарь `parameters`, перейдите на публичные методы получения метаданных и расширения. Для числовых результатов используйте сравнение с допуском, а для твёрдости обрабатывайте `None`. Подробнее — в [истории изменений](../CHANGELOG.md).
